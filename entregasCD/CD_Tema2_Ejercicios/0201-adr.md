# ADR 0201: Uso de Git y Markdown para la documentación y entrega de prácticas

* **Estado:** Aceptado
* **Fecha:** 2026-11-08
* **Autores:** Estudiante

---

## Contexto y Problema
Para la realización y entrega de las actividades de las unidades de la asignatura, necesitamos un sistema que permita registrar de forma estructurada tanto los enunciados y soluciones de los ejercicios como las decisiones de arquitectura, garantizando el versionado y la trazabilidad de los cambios.

---

## Opciones Consideradas

1. **Opción 1: Documentos ofimáticos estáticos (PDF o Word)**
   * *Ventajas:* Formato conocido y fácil de redactar inicialmente.
   * *Desventajas:* Dificultad para realizar un control de cambios preciso, integrar revisiones automáticas y mantener una estructura de repositorio limpia.

2. **Opción 2: Archivos Markdown (`.md`) gestionados con Git**
   * *Ventajas:* Texto plano altamente legible, integración nativa con plataformas de control de versiones (GitHub) y facilidad para versionar cada ejercicio de forma independiente mediante commits.
   * *Desventajas:* Curva de aprendizaje inicial en el uso de comandos de Git.

---

## Decisión Tomada
Se decide utilizar **Markdown (`.md`) para la redacción de los contenidos** y **Git (GitHub) como sistema de control de versiones y repositorio oficial** para todas las entregas de las unidades.

---

## Consecuencias

### Positivas:
* **Trazabilidad total:** Permite al profesor revisar el historial de commits, las fechas y los cambios exactos de cada ejercicio.
* **Estandarización:** Facilita la lectura directa de los documentos en la interfaz web de GitHub sin necesidad de herramientas externas.

### Negativas / Riesgos:
* Posibles errores humanos al ejecutar comandos en la terminal, mitigados mediante la adopción de un flujo de trabajo estándar (`add`, `commit`, `push`).
